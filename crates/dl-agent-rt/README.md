# dl-agent-rt

The `dl-rt/1` session protocol of [ADR 0011](../../docs/decisions/0011-realtime-lan-first-sync.md)
(D3): one long-lived duplex session per agent carrying capture batches, commands, results,
control messages and bulk data. This crate is the transport-neutral part, with no sockets,
no clocks and no storage of its own: time comes in as `u64` microseconds and the caller
moves the bytes (one frame per WebSocket binary message).

- **Frame codec**: version byte, big-endian fixed 24-byte header, explicit payload length,
  optional per-hop timestamp extension (`t_detected_us`, `t_read_us`), size limit (default
  1 MiB) and a typed [`Error`] for every malformed input. Never panics on untrusted bytes.
- **Sender** ([`ChannelSender`]): monotonic seq per channel, unacknowledged frames kept for
  resend, cumulative acks, per-channel byte credit (no credit means "would block", never drop),
  resume from the peer's high-water mark.
- **Receiver** ([`ChannelReceiver`]): dedupe by (channel, seq), gap detection, acks only after
  the caller commits, credit grants, `resume_ok` with the high-water mark.
- **Session** ([`Session`]): five channels both ways, the connect/resume handshake, ping/pong,
  close, and the writer priority control > capture/commands/results > bulk.

The wire format and rules are specified in
[`docs/protocol/dl-rt-1.md`](../../docs/protocol/dl-rt-1.md), so the PDAOrder cloud can
implement the other end in .NET; `testdata/frames.txt` holds golden vectors for both sides.

```rust
use dl_agent_rt::{Channel, Config, Event, Ext, Frame, Outcome, Session};

let config = Config::default();
let (mut agent, mut cloud) = (Session::new(config), Session::new(config));

// Moves every queued frame from one end to the other through the wire format.
fn pump(from: &mut Session, to: &mut Session, now_us: u64) -> Vec<Event> {
    let mut events = Vec::new();
    while let Some(frame) = from.poll_outgoing() {
        let bytes = frame.encode(&from.config().limits).unwrap();
        let frame = Frame::decode(&bytes, &to.config().limits).unwrap();
        events.push(to.handle(frame, now_us).unwrap());
    }
    events
}

// A new connection: both ends resume every channel and grant initial credit.
agent.connect(0);
cloud.connect(0);
pump(&mut agent, &mut cloud, 1);
pump(&mut cloud, &mut agent, 2);
pump(&mut agent, &mut cloud, 3);

// A capture batch goes up, the cloud applies and commits it, the ack comes back.
let Outcome::Done(seq) = agent.send(Channel::Capture, b"batch".to_vec(), Ext::NONE, 10).unwrap()
else { panic!("no credit") };
let events = pump(&mut agent, &mut cloud, 20);
assert!(matches!(&events[..], [Event::Data(f)] if f.payload == b"batch"));
cloud.commit(Channel::Capture, seq, 30).unwrap();
let events = pump(&mut cloud, &mut agent, 40);
assert_eq!(events, [Event::Acked { chan: Channel::Capture, through: 1, released: 1 }]);
```

## Tests

- `tests/golden.rs`: the vectors in `testdata/frames.txt`, generated by
  `testdata/gen_frames.py` from the protocol document (Python `struct`, independent of this
  crate), checked both ways.
- `tests/props.rs`: random interleavings (xorshift64*, no third-party crates) of send,
  credit, delivery, commit, dropped connections, resume and resend between two sessions end
  with every payload applied exactly once in order per channel; random and mutated bytes
  never make the decoder panic.
