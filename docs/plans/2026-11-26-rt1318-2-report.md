# RT-1318 slice 2 report: dl-rt/1 session protocol crate

Brief: [2026-11-26-rt1318-s2-brief.md](2026-11-26-rt1318-s2-brief.md). Branch `feat/rt-1318-session-codec`.

## What was built

- New crate `crates/dl-agent-rt` (workspace member, listed in `[workspace.dependencies]`):
  `#![no_std]` + `alloc`, `#![forbid(unsafe_code)]`, zero dependencies (also no dev-dependencies),
  no I/O, no clock (every call takes `now` in microseconds). Builds for `wasm32-unknown-unknown`.
- Frame codec (`frame.rs`, `codec.rs`): version byte 1, big endian, 24-byte fixed header, explicit
  `payload_len`, optional extension (tagged u64 entries: `t_detected_us`, `t_read_us`; unknown tags
  skipped), `Limits` with 1 MiB default `max_frame`, exact-length check (truncated / trailing),
  kind rules (`Frame::validate`) enforced on both encode and decode. Five channels, eight kinds.
- `ChannelSender` (`sender.rs`): monotonic seq, unacked queue, cumulative acks, byte credit that
  returns `Outcome::WouldBlock` with the payload handed back (never dropped), resume frame on
  connect, release on `resume_ok` and in-order resend from hwm+1 (new sends wait until it ends),
  `restore` from a persisted outbox.
- `ChannelReceiver` (`receiver.rs`): dedupe (`Delivery::Duplicate`), gap detection, ack only on
  `commit(seq)`, credit grants and enforcement (`credit_exceeded`), `resume_ok` with the committed
  hwm, `rewind` for lost uncommitted frames, `with_hwm` rebuild.
- `Session` (`session.rs`): five sender/receiver pairs, resume handshake on every connection,
  initial credit from `Config`, writer priority control > capture/commands/results > bulk (FIFO
  inside a class, bulk on its own credit), ping/pong with RTT, close, `handle(frame) -> Event`.
- One typed `Error` (`error.rs`, `#[non_exhaustive]`) with stable `name()`s shared with the spec.
- Spec `docs/protocol/dl-rt-1.md`: byte layout of every kind, worked examples, decode order,
  sender/receiver/session rules, limits, close codes, error names, golden vector format.
- Golden vectors `crates/dl-agent-rt/testdata/frames.txt` (54: 21 valid, 33 malformed), generated by
  `testdata/gen_frames.py` with Python `struct` from the spec, not from the Rust code.

## Public API

`Frame`, `Channel`, `Kind`, `Ext`, `CloseCode`, `Limits`, `Error`; constants `VERSION`,
`HEADER_LEN`, `EXT_ENTRY_LEN`, `DEFAULT_MAX_FRAME`, `MAX_CLOSE_REASON`, `FLAG_EXT`,
`TAG_T_DETECTED`, `TAG_T_READ`; `ChannelSender`, `SenderState`, `Outcome`, `WouldBlock`,
`Blocked`, `Resend`; `ChannelReceiver`, `Delivery`; `Session`, `Config`, `SessionState`, `Event`.
Entry points: `Frame::encode/encode_into/decode`, `Session::{connect, send, poll_outgoing, handle,
commit, grant, ping, close, disconnect, rewind, from_parts}`, `ChannelSender::restore`,
`ChannelReceiver::with_hwm`. Every public item is documented (`cargo doc` with `-D warnings` clean).

## Not done / risks

- Out of scope as briefed: sockets, TLS, WebSocket, persistence (outbox.db), cloud .NET code,
  dl-agent-pda-sync changes. The persistence contract the state machines expect is written in the
  spec (store before write, delete through acked, `restore` / `with_hwm`).
- Bulk on a second WebSocket connection: the protocol allows it (rules are per channel), but
  `Session` models one connection; splitting bulk out is left to the transport slice.
- Credit counts payload bytes only (not header/ext), and duplicates and resends are charged too, on
  both sides; the .NET end must count the same way or it will report `credit_exceeded`.
- No length-prefixed stream helper (only needed for a non-WebSocket transport later).
- `close` is per connection; no graceful-drain timeout is in the crate (the caller owns timers).
- Version negotiation beyond the version byte is not defined; a version 2 needs a new spec.
