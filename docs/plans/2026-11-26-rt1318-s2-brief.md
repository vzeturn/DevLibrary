# RT-1318 slice 2: dl-rt/1 session frame codec + seq/ack/credit/resume state machine (pure, no I/O)

## Goal
New crate `crates/dl-agent-rt` (workspace member; builds for wasm32-unknown-unknown; `#![forbid(unsafe_code)]`) holding the
transport-neutral session protocol of ADR 0011 D3, with no sockets and no clocks of its own (time is passed in as `u64` microseconds).
It will be used by the agent session client (slice 5, over dl-ws) and re-implemented by the PDAOrder cloud in .NET (slice 3), so the
wire format must be specified in a document and pinned by golden vectors that a .NET test can read.

## Scope
1. Frame codec. Start from the spike's format in `spikes/dl-rt-transport/src/frame.rs` (`chan | kind | seq | sent_us | payload`) and make it a
   production codec: fixed little/big endian (pick one, document it), version byte, explicit lengths, max frame size (configurable, default 1 MiB),
   typed `Error` for every malformed input (truncated, unknown version, oversize, bad channel/kind). Channels: control, capture, commands, results, bulk.
   Kinds at least: data, ack (cumulative per channel), credit (grant bytes per channel), resume (chan, last_acked), resume_ok (chan, high-water mark),
   ping, pong, close (reason code). Per-hop timestamps must fit: data frames carry `sent_us`; allow an optional small header-extension area for
   `t_detected`/`t_read` (ADR "Each hop is measured").
2. Sender state machine (one per channel, plus a session wrapper): assigns monotonic seq, keeps unacked frames (in memory, but behind a small
   trait or returned values so slice 5/6 can persist them in outbox.db), applies cumulative acks, enforces credit (bytes granted per channel; no credit
   = `would_block`, never drop), and on reconnect produces the resume frames and, given resume_ok, the frames to resend (from hwm+1). Bulk never uses
   control/capture credit; writer priority control > capture/commands/results > bulk.
3. Receiver state machine: dedupe by (chan, seq) (duplicates are reported as duplicates, not errors), detect gaps, produce cumulative acks
   (ack after the caller says the frame is durably committed: API like `commit(chan, seq)` -> ack frame), grant credit, answer resume with its hwm.
4. Docs: `docs/protocol/dl-rt-1.md` - byte layout of every frame kind, the state machine rules (seq/ack/credit/resume/close), error handling,
   and the limits. Written so a .NET engineer can implement the cloud side without reading Rust.
5. Golden vectors: `crates/dl-agent-rt/testdata/frames.txt` (or .json via dl-json): name, hex bytes, decoded fields; written BY HAND from the spec
   (byte layout computed independently, e.g. a tiny script or worked by hand in the doc), and checked both ways in tests (encode == hex, decode == fields).
6. Tests: unit + property-style tests without third-party crates (use `dl-rand` or a small xorshift in tests): random interleavings of
   send/ack/credit/drop-connection/resume/duplicate delivery must end with every frame delivered exactly once in order per channel; fuzz-ish decode of
   random bytes must never panic.

## Out of scope
Any socket, TLS, WebSocket, persistence, cloud code, or changes to dl-agent-pda-sync.
