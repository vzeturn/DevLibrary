## Wire fields (both repos, optional and additive)

All stamps are unix-epoch **microseconds** (`i64` / `long?`), omitted from the JSON when unknown, written after the
existing members so an older reader sees the same object plus unknown members.

| Envelope | Field (JSON) | .NET | Meaning |
|---|---|---|---|
| batch (`SyncBatch`) | `t_detected` | `TDetected` | start of the capture pass that produced the batch |
| batch | `t_read` | `TRead` | rows read from SMILE, batch built (start of `BatchWriter::flush`) |
| batch | `t_sent` | `TSent` | handed to the HTTP transport; added to the stored outbox payload on every post |
| command result (`SyncCommandResult`) | `t_received` | `TReceived` | socket frame read / poll response received |
| command result | `t_started` | `TStarted` | handler started |
| command result | `t_finished` | `TFinished` | outcome known, before the result is sent |

Cloud-side stamps (not on the wire): `t_recv` when the service gets the request, `t_committed` after its commit, plus
`created_at` / `dispatched_at` / `completed_at` of `sync.commands`.

## DevLibrary (crate dl-agent-pda-sync)

- `src/util/hop_clock.rs` (new): the one monotonic+wall clock. Anchors wall time to an `Instant`, follows the monotonic
  clock, re-anchors when wall and monotonic drift apart by more than `RESYNC_US` = 2 ms, holds a small step back (<= 2 ms)
  at the last stamp, follows a large step back. A wall clock before the epoch gives no stamp; a poisoned lock is
  recovered; nothing panics. `PassStamp` (RAII, thread-local) marks the start of a capture pass.
- `src/contracts/wire/hops.rs` (new): `BatchHops`, `ResultHops` (nested `hops` member on the Rust structs, flat on
  the wire) and `with_t_sent(payload, at)`, which splices `,"t_sent":N` before the closing brace of a stored payload
  and leaves anything else (empty, not an object, `{}`, already stamped) unchanged.
- `envelope.rs`: read/write of the six fields. Every struct literal got `hops: Default::default()`.
- Capture: `scheduler::run_job` opens a `PassStamp`; `capture/writer.rs` stamps `t_detected` (pass start) and
  `t_read`. Outbox: `batch_uploader.rs` posts `with_t_sent(payload, now)` (also for orphan skips).
- Commands: `channel.rs` stamps `t_received` when the socket text frame is read (before parsing) or when the poll
  response arrives, `t_started`/`t_finished` around `handle_guarded`/`handle`. A remembered result (redelivery) is
  stored without stamps and stamped per delivery; the cloud counts only the first result of a command, so a redelivery
  does not skew the histograms. `result_outbox.rs` needed no change: results are stamped before they are queued, so the
  HTTP fallback carries the same stamps.
- `executor.rs`: `payload()` returns `Result<T, Box<SyncCommandResult>>` (clippy `result_large_err`: the result grew
  from under 128 to 160 bytes). Mechanical, same behaviour.
- Tests: `src/contracts/tests/hops.rs` (goldens byte-for-byte equal to PDAOrder `EnvelopeTests`
  `Batch_and_result_carry_optional_hop_stamps`, none written when null, `with_t_sent` cases), unit tests in
  `hop_clock.rs` (8, including step-back and pre-epoch cases), `src/capture/hop_stamp_tests.rs`,
  `tests/outbox_hop_stamps.rs`, a new case in `tests/commands_channel.rs`. The two redelivery tests in
  `tests/commands_result_delivery.rs` now compare the stored result without its per-delivery stamps. The existing .NET
  golden in `contracts/tests/dotnet.rs` is unchanged and still green (null stamps write nothing).

## Risks and notes

- **Criterion (a) caveat.** `t_detected` is the start of the capture pass, not the moment SMILE wrote the row: the wait
  from the SMILE write to the next pass (poll interval) cannot be seen by the agent and is not in any hop. The .NET doc
  comment says "when the agent saw the earliest change of the batch", which is what the pass start is.
- `cross` hops carry the agent-cloud clock offset; a skew-free reading of criterion (a) is
  `capture.detect_sent` + `command.oneway_est` + `capture.recv_commit` (documented in OBSERVABILITY-CLOUD.md).
- A span that straddles a large wall-clock step on the agent is off once (a negative span lands in bucket 0,
  `below_zero`); the clock re-anchors right after.
- `t_sent` is rewritten per post attempt, so a retried batch reports its last attempt; `capture.read_sent` then includes
  the outbox wait, which is intended (it is the backlog signal).
- Over-limit files (pre-existing, not split here to keep the slice small): `src/commands/executor.rs` 1034 lines (was
  1032 before `hops` literals) and `src/contracts/tests/dotnet.rs` 862 (was 859). `channel.rs` is 756 and
  `batch_uploader.rs` 750, both under 800.
- Commit trailer: the launch message asked for "Claude Sonnet 5.5"; the brief and the session's attribution rule say
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, which matches the model that did the work, so that one was used.
- Cloud and agent ship independently: an old agent sends no stamps and the cloud still records the cloud-only hops; an
  old cloud ignores the new members (System.Text.Json default, unknown members skipped).
