# RT-1318 slice 12a: dl-tls server side, report

Brief: `docs/plans/2026-11-26-rt1318-s12a-brief.md`. Branch `feat/rt-1318-tls-server` (worktree
`DevLibrary-wt-1318-s12a`). Not pushed, merged or deployed.

## What was built

`dl-tls` now has a TLS 1.2/1.3 server side for the LAN edge (ADR 0011 D1, row 12a), with the
same `TlsStream` as the client and still no third-party crates (none in dev-dependencies either).

- **Backend-independent prelude** (`src/server.rs`, `src/client_hello.rs`, `src/alpn.rs`):
  before the OS stack runs, `accept` reads the whole ClientHello (record layer, may be split
  over records, at most 64 KiB) and extracts SNI (RFC 6066 §3) and the ALPN offer
  (RFC 7301). ALPN is chosen by server preference. When the client offers ALPN but nothing
  matches, dl-tls itself sends the fatal `no_application_protocol` alert (120) and returns
  `Error::Handshake { code: 120 }`. The bytes it read are handed to the OS stack unchanged,
  so both backends show the same SNI and ALPN behaviour. Malformed input is an error, never a
  panic (corruption tests flip every byte of a real hello).
- **PKCS#8 parsing** (`src/pkcs8.rs`): `PrivateKey::from_pkcs8_der` recognises unencrypted
  PKCS#8 (RFC 5208) for ECDSA P-256 and RSA, and refuses other curves (P-384 test key) or
  algorithms with `InvalidInput`. The key bytes are zeroed on drop, and `Debug` shows only
  the algorithm.
- **Linux / OpenSSL** (`src/openssl.rs`, `src/openssl_sys.rs`): `TLS_server_method` with
  memory BIOs. libssl is still loaded with `dlopen`, now with the extra server symbols. The
  ALPN select callback returns the protocol already chosen by the prelude. The chain is set
  with `SSL_CTX_use_certificate_ASN1` plus `SSL_CTX_add0_chain_cert`, and the key with
  `d2i_PKCS8_PRIV_KEY_INFO`, `EVP_PKCS82PKEY`, `SSL_CTX_use_PrivateKey` and
  `SSL_CTX_check_private_key`, so a mismatched key fails when the credential is built.
- **Windows / SChannel** (`src/schannel.rs`, `src/schannel_sys.rs`,
  new `src/schannel_server_sys.rs`):
  - Credentials use `AcquireCredentialsHandleW` (inbound) with `SCH_CREDENTIALS`, falling
    back to the legacy `SCHANNEL_CRED`. The server protocol bits come from `min_version`.
    The flags are `SCH_CRED_NO_SYSTEM_MAPPER | SCH_USE_STRONG_CRYPTO`.
  - The handshake uses `AcceptSecurityContext`, and ALPN goes in
    `SECBUFFER_APPLICATION_PROTOCOLS` on the first call. Shutdown uses `ApplyControlToken`
    followed by ASC.
  - The key is imported with CNG (`NCryptImportKey`, PKCS8_PRIVATEKEY blob, Microsoft
    Software KSP, silent). The code first tries an **ephemeral** key attached with
    `CERT_NCRYPT_KEY_HANDLE_PROP_ID`. If SChannel refuses it at
    `AcquireCredentialsHandle`, the code imports a **temporary persisted** key named
    `dl-tls-<pid>-<n>-<nanos>`, attaches it with `CERT_KEY_PROV_INFO_PROP_ID`, and deletes it
    (`NCryptDeleteKey`) when the credential is dropped.
  - Chain intermediates are added to the system `CA` store (LocalMachine first, then
    CurrentUser), because SChannel sends the chain it builds from the system stores.
  - The session code is shared with the client through an internal `Peer::{Client, Server}`.
- **macOS and wasm** (`src/unsupported.rs`): `accept` returns `Error::Unsupported`. The
  credential is still validated first, so configuration errors stay the same on every
  platform.
- **One credential per config:** the first `accept` builds the OS credential and caches it
  in the `ServerConfig` (`Arc<Mutex<..>>`). Clones and concurrent connections share it.
- **Test certificates** in `crates/dl-tls/testdata/`:
  - They are generated by `gen.sh` with the OpenSSL CLI, an independent implementation.
  - They are marked TEST-ONLY in `gen.sh` and in the subjects (`O=dl-tls test only`).
  - Files: self-signed EC and RSA leaves, a root, an intermediate, a leaf for the chain, and
    a P-384 key used only to test refusal.

## Public API (new)

```rust
pub enum KeyAlgorithm { EcdsaP256, Rsa }
pub struct PrivateKey;               // Debug (algorithm only), zeroed on drop; shared via Arc in ServerConfig
impl PrivateKey {
    pub fn from_pkcs8_der(der: &[u8]) -> Result<PrivateKey, Error>;
    pub fn algorithm(&self) -> KeyAlgorithm;
}
pub struct ServerConfig;             // Clone (shares the OS credential), Send + Sync
impl ServerConfig {
    pub fn new(cert_chain_der: Vec<Vec<u8>>, private_key: PrivateKey) -> ServerConfig;
    pub fn alpn(self, protocols: &[&[u8]]) -> ServerConfig;      // server preference order
    pub fn min_version(self, version: Version) -> ServerConfig;  // default Tls12
    pub fn cert_chain_der(&self) -> &[Vec<u8>];
    pub fn private_key(&self) -> &PrivateKey;
    pub fn alpn_protocols(&self) -> &[Vec<u8>];
    pub fn minimum_version(&self) -> Version;
}
impl<S: Read + Write> TlsStream<S> {
    pub fn accept(config: &ServerConfig, stream: S) -> Result<TlsStream<S>, Error>;
    pub fn server_name(&self) -> Option<&str>;   // client's SNI; None on client sessions
}
```

`version`, `alpn_protocol`, `read`, `write`, `shutdown` and `into_parts` work the same on
server sessions. `peer_certificate_der` is `None` on server sessions because client
certificates are out of scope. The `Error` enum is unchanged.

## Tests and results

Tests were written first (`tests/server.rs` and the unit tests), then the code. The expected
values come from the RFCs: the RFC 8448 ClientHello, the RFC 7301 alert code, and
RFC 5208/5480/8017 OIDs. The peers used are OpenSSL CLI certificates, `curl`, and
`openssl s_client`.

`tests/server.rs` has 12 tests:
- 1 MiB each way between the dl-tls client and server, with ALPN, SNI and peer certificate.
- An RSA key.
- A TLS 1.3 minimum.
- No SNI and no ALPN.
- ALPN with no overlap, which must give alert 120.
- Garbage input and an early close.
- An unusable certificate, which must fail before reading.
- A key belonging to another certificate.
- 4 concurrent connections on one config with a chain.
- curl verifying the chain via `--cacert` (default, and `--tls-max 1.2`).
- curl below the minimum version, which must be refused.
- `openssl s_client -verify_return_error`, which must give "Verify return code: 0 (ok)"
  and "ALPN protocol: http/1.1".

## Risks and notes for review

1. **Windows key form:** the brief asked for an ephemeral key. On Server 2022 SChannel
   refuses it, so the code falls back to a temporary persisted key in the user's Software
   KSP. That key is deleted on drop, but a process that is killed can leave
   `dl-tls-*` keys behind; the README documents `certutil ... -key -user` and `-delkey`. The
   ephemeral attempt costs one failed ACH per `ServerConfig`. If a future Windows accepts
   the ephemeral key at ACH but fails at ASC, handshakes would fail. Making the persisted key
   the only path is a two-line change if review prefers predictability.
2. **CA store side effect (Windows):** intermediates are added to LocalMachine\CA (or
   CurrentUser\CA) and stay there. This is needed for SChannel to send the chain, and the
   README documents it. Intermediates are public data, but this is still a change to
   machine state.
3. **New Windows import:** `ncrypt.dll` (CNG, a system DLL since Vista) is now linked for
   every Windows user of dl-tls. The root README's OS-library line was updated.
4. **Client behaviour change (legacy credentials):** the legacy protocol mask now drops the
   TLS 1.3 bits. When that leaves nothing (`min_version(Tls13)` on pre-1809 Windows), it
   returns `SEC_E_ALGORITHM_MISMATCH`. Before, a zero mask meant "system defaults", which
   could negotiate below the requested minimum. That was a latent bug; the fix is stricter.
5. **Message wording:** two SChannel handshake messages changed from "server" to "peer" (for
   example "the peer rejected the handshake (illegal message)"), and
   `SEC_E_UNKNOWN_CREDENTIALS` got its own message. Error variants and codes are unchanged.
   Only code that matches on message text would notice.
6. **Key mismatch timing:** OpenSSL refuses a mismatched key when the credential is built.
   SChannel only fails during the handshake (the client rejects the signature). Both are
   documented and tested.
7. **Unauthenticated work before the OS stack:** the prelude buffers up to 64 KiB of
   ClientHello per connection before the OS stack sees it. Callers should set a read timeout
   (documented on `accept`) so a silent client cannot hold a thread.
8. **Size:** the largest file is `src/schannel_sys.rs` (739 lines), which is under 800. All
   `unsafe` is in `*_sys.rs` files with `// SAFETY:` comments.
