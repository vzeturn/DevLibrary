# RT-1318 slice 8: SQL Server Change Tracking probe + enable step in the pda-sync grants bootstrap

## Goal
Make dl-agent-pda-sync able to turn on SQL Server Change Tracking (CT) for the SMILE_POS tables it captures, idempotently and only behind a flag
(default OFF), so slice 9 can read changes by version instead of polling signatures. Nothing changes on any site while the flag is off.

## Design (ADR 0011 D2 - read it)
- Flag: runtime option `capture.change_tracking` (follow how other pda-sync options are declared in `crates/dl-agent-pda-sync/src/config/options.rs`
  and read from the hub/site config); default false.
- Probe (read-only, as the `pda_sync` login): is CT on for the database (`sys.change_tracking_databases`), which captured tables are tracked
  (`sys.change_tracking_tables`), does each captured table have a primary key, does `pda_sync` have `VIEW CHANGE TRACKING` on it
  (`HAS_PERMS_BY_NAME(..., 'OBJECT', 'VIEW CHANGE TRACKING')`), and `CHANGE_TRACKING_CURRENT_VERSION()`.
- Enable (only when the flag is on), run by the same bootstrap identities as the grants self-repair of ADR 0010
  (`crates/dl-agent-pda-sync/src/commands/grants_repair.rs`, `hosting/grants.rs`, `docs/decisions/0010-pda-sync-self-healing.md`): the service's Windows
  identity first, then after an access refusal the SMILE default SQL login. NEVER alter any login or password.
  1. `ALTER DATABASE <db> SET CHANGE_TRACKING = ON (CHANGE_RETENTION = 2 DAYS, AUTO_CLEANUP = ON)` if not on (quote names properly, parameterize what can be).
  2. Per captured table WITH a primary key and not yet tracked: `ALTER TABLE <t> ENABLE CHANGE_TRACKING WITH (TRACK_COLUMNS_UPDATED = OFF)`.
     Tables without a PK are skipped and reported (they stay on signature polling).
  3. `GRANT VIEW CHANGE TRACKING ON <t> TO pda_sync` per tracked table.
  4. Set `lock_timeout` (e.g. `SET LOCK_TIMEOUT 5000`) so an ALTER never blocks POS writes for long; a timeout is a retryable, reported failure.
  Must work on SQL Server 2008 R2 .. 2022 syntax (Express included); no CDC, no Service Broker, no triggers.
- Where it runs: as part of the existing grants bootstrap / self-repair cycle (15-minute retry while missing), and in the `grants` verb.
- Site events (follow `contracts/wire/site_events.rs` and existing codes in `hosting/grants.rs`): e.g. `CAPTURE_CT_ENABLED` (tables tracked, identity used),
  `CAPTURE_CT_PARTIAL` (tables skipped and why: no_pk / refused), `CAPTURE_CT_FAILED` (per identity outcome, never a password). Keep them in the
  existing style. Also expose the probe result in the selftest/status the module already reports if that is a small addition.
- Reversibility: add a disable path used by tests/ops (`ALTER TABLE .. DISABLE CHANGE_TRACKING`; DB-level off only when no tracked tables remain), not wired to
  any automatic trigger.

## Tests
- Unit tests for the SQL text builders and the decision logic (which tables, which steps, idempotency, flag off = no statement issued).
- Live tests gated on `PDA_SYNC_TEST_SQL` (see `crates/dl-agent-pda-sync/tests/live_smile_pos.rs` and `crates/dl-agent-pda-sync/scripts/live-sql.sh`
  which runs them on throwaway SQL Server 2017 and 2022 containers): enable twice (idempotent), a table without PK is skipped, a DML on a tracked table
  moves `CHANGE_TRACKING_CURRENT_VERSION()` and shows in `CHANGETABLE(CHANGES ...)` read as `pda_sync`, and a low-privilege identity gets a clear refusal.
  Run live-sql.sh (OrbStack is available) and remove the containers after.
