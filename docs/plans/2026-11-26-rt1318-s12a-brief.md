# RT-1318 slice 12a: dl-tls server mode (SChannel AcceptSecurityContext on Windows, OpenSSL on Linux)

## Goal
`crates/dl-tls` is client-only today. Add a server side so the agent can later serve the LAN edge (`https://<site>.lan.<domain>`, ADR 0011 D1)
over TLS 1.2/1.3 with a real certificate whose private key was generated on the machine.

## Scope
- Public API mirroring the client: e.g. `ServerConfig::new(cert_chain_der: Vec<Vec<u8>>, private_key: PrivateKey)` with `PrivateKey` from PKCS#8 DER
  (support ECDSA P-256 at least; RSA 2048 if cheap), optional ALPN list (h2 not needed; `http/1.1`), minimum version (default TLS 1.2), and
  `TlsStream::accept(&ServerConfig, stream) -> Result<TlsStream<S>, Error>`; the resulting stream is the same `TlsStream<S>` type with Read/Write, `alpn_protocol`,
  `version`, `shutdown`. Expose the SNI the client sent (needed for the Host/SNI check of the edge).
- Windows: SChannel server credentials (`AcquireCredentialsHandle` with SCHANNEL_CRED / SCH_CREDENTIALS and a `PCCERT_CONTEXT` whose key is a CNG key
  imported from the PKCS#8 bytes via `NCryptImportKey`, ephemeral / not persisted, attached with `CERT_NCRYPT_KEY_HANDLE_PROP_ID` or equivalent),
  `AcceptSecurityContext` loop, then the existing record encrypt/decrypt path. Follow the style of `src/schannel.rs` / `src/schannel_sys.rs` (hand-written FFI).
- Linux: OpenSSL server via the existing `src/openssl_sys.rs` loading approach (`SSL_CTX_new(TLS_server_method())`, use_certificate / use_PrivateKey from DER,
  `SSL_accept`), used for tests in a Linux container.
- macOS / wasm: `unsupported` like the client (compile, return a typed error).
- Read how dl-tls is tested today (`tests/network.rs`, `tests/legacy_server.rs`, scripts under `scripts/xbuild`) and test the same way: a loopback test that
  accepts with dl-tls server and connects with dl-tls client (and, independently, with the OS's `openssl s_client` / curl as the reference peer) on Linux
  (OrbStack container), and the Windows build checked at least with the repo's cross-build (`scripts/xbuild`) plus, if the repo has a way to run Windows
  tests (`win-run`), a loopback test on Windows. Test certificates: generate at test time or commit a test-only self-signed cert+key under testdata
  (clearly test-only, never a real key).
- Update `crates/dl-tls/README.md` (server example that compiles) and the "Planned next" mention if relevant.

## Out of scope
HTTP server, WebSocket server, ACME, key generation/CSR (later slices), client cert auth.
