# RT-1318 slice 1: per-hop latency stamps (agent) + per-site latency metrics (PDAOrder cloud)

## Goal
Before changing the transport we must MEASURE each hop on the running product (MuineBay canary), because RT-1318 is accepted only on measured
p50/p95 per criterion: (a) SMILE change -> cloud commit p50 <= 40 ms, p95 <= 70 ms; (b) cloud command -> store -> result back p95 <= 100 ms.

### PDAOrder part
- Find the agent ingest endpoint(s) (`/sync/v1/...` batch POST used by the Rust agent `dl-agent-pda-sync` and the .NET `apps/sql-sync-agent`) and the
  command path (`sync.commands`, `/sync/v1/commands/ws`, result post, `result_ack` frame).
- Accept OPTIONAL per-hop stamps (unix epoch microseconds, int64) without breaking older agents: on a capture batch `t_detected` (agent saw the change),
  `t_read` (rows read), `t_sent` (batch handed to the transport); on a command result `t_received` (agent got the command), `t_started`, `t_finished`.
  The cloud stamps `t_recv` (request/frame received) and `t_committed` (durable commit). For commands: add `dispatched_at` (pushed on the socket)
  and use `created_at` / `completed_at` of `sync.commands` (new numbered migration, `lock_timeout`, follows repo migration rules).
- Store latency observations cheaply: per tenant, per hop, per minute histogram buckets (fixed log-scale buckets, e.g. 1,2,5,10,20,30,40,50,70,100,150,200,300,500,1000,2000,5000,+inf ms)
  in a small table (upsert counter per bucket) or an in-memory aggregator flushed every N seconds - pick the cheaper safe option, no per-event row.
  Clock skew: agent-vs-cloud hops cross two clocks; also store the same-clock spans (cloud: recv->commit, command created->completed; agent: detected->sent,
  received->finished) which are skew-free, and estimate one-way as (round trip - agent span)/2 where possible. Document which numbers are skew-free.
- Expose read-only: an admin/ops API route (follow existing admin route conventions and auth) returning p50/p95/p99 + count per hop for a tenant and a time window,
  and add it to the platform MCP diagnose output if that is a small change (`pdaorder_diagnose`). Tests with the repo's test conventions (real Postgres via Testcontainers if the repo uses it).
### DevLibrary part (`crates/dl-agent-pda-sync`)
- Send the stamps: capture batches (outbox -> batch uploader; envelope in `src/contracts/wire/envelope.rs`), command results (`src/commands/result_outbox.rs`, `channel.rs`).
  Fields optional and additive; keep the contract tests (`src/contracts/tests/*`, .NET goldens) green - if goldens pin the exact JSON, extend them consistently.
- Use one monotonic+wall clock helper; never panic on clock going backwards.
