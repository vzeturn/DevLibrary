# dl-rt/1: session frame protocol

- Status: draft, implemented by `crates/dl-agent-rt` (Rust, agent side); the PDAOrder cloud
  implements the other end in .NET (RT-1318 slice 3).
- Design: [ADR 0011](../decisions/0011-realtime-lan-first-sync.md), D3.
- Golden vectors: [`crates/dl-agent-rt/testdata/frames.txt`](../../crates/dl-agent-rt/testdata/frames.txt),
  generated by `testdata/gen_frames.py` from this document.

One long-lived duplex session per agent carries capture batches up, commands down, results up,
control messages both ways and bulk data. Each end runs the same rules: for each of the five
channels it has a **sender** (its outgoing data) and a **receiver** (the peer's data). This
document is enough to implement either end without reading the Rust code.

## 1. Transport

- One frame = one WebSocket **binary** message (RFC 6455). Frames are never split or merged.
- A byte-stream transport (for example QUIC, later) prefixes each frame with its length as a
  u32, big endian; the length is not part of the frame.
- Bulk may run on a second WebSocket connection of the same session (ADR 0011 D3) so a lost
  bulk segment does not block the other channels. The rules below are per channel, so they do
  not change.
- The connection is authenticated before the first frame (signed upgrade, ADR 0011 D3).

## 2. Frame layout

All integers are unsigned and **big endian** (network order).

| Offset | Size | Field | Notes |
|---:|---:|---|---|
| 0 | 1 | `version` | `1`. Any other value: error `version`. |
| 1 | 1 | `chan` | 0 control, 1 capture, 2 commands, 3 results, 4 bulk. Else `channel`. |
| 2 | 1 | `kind` | 1 data, 2 ack, 3 credit, 4 resume, 5 resume_ok, 6 ping, 7 pong, 8 close. Else `kind`. |
| 3 | 1 | `flags` | bit 0 (`0x01`) = extension present. Bits 1-7 reserved, must be 0, else `flags`. |
| 4 | 8 | `seq` | u64, meaning depends on the kind (section 3). |
| 12 | 8 | `sent_us` | u64, sender clock in microseconds when written (Unix epoch on the agent). |
| 20 | 4 | `payload_len` | u32, bytes of payload. |
| 24 | 1 | `ext_len` | **only if flags bit 0**: bytes of extension entries; a non-zero multiple of 9. |
| 25 | ext_len | entries | **only if flags bit 0**: `ext_len / 9` entries of `tag u8, value u64`. |
| 24 or 25 + ext_len | payload_len | `payload` | opaque bytes. |

Total length = 24 + (flags bit 0 ? 1 + ext_len : 0) + payload_len, **exactly**: the message
must be neither shorter (`truncated`) nor longer (`trailing`).

### Extension entries (per-hop timestamps)

Only data frames carry an extension (ADR 0011, "Each hop is measured"; `t_sent` is `sent_us`).

| Tag | Name | Meaning |
|---:|---|---|
| 0 | - | reserved: error `ext` |
| 1 | `t_detected_us` | when the change was detected on site |
| 2 | `t_read_us` | when the changed rows were read |
| 3-255 | - | unknown: **skipped** by the decoder (forward compatibility) |

A known tag (1 or 2) appearing twice is error `ext`. An encoder writes entries in tag order
and omits the extension (flags = 0) when no timestamp is set. Since unknown tags are skipped,
a decoded frame can re-encode to fewer bytes; that is expected.

### Worked example

Data frame on capture, seq 1, sent_us 1000, payload `abc` (vector `data_capture_basic`):

```text
01                        version 1
01                        chan capture
01                        kind data
00                        flags: no extension
00 00 00 00 00 00 00 01   seq 1
00 00 00 00 00 00 03 e8   sent_us 1000
00 00 00 03               payload_len 3
61 62 63                  payload "abc"
```

Same with `t_read_us = 15` (vector `data_capture_ext_read_only`, seq 2, sent_us 20, payload `x`):
flags `01`, then after the 24-byte header `09` (ext_len), `02 00 00 00 00 00 00 00 0f`
(tag 2, value 15), then `78`.

## 3. Frame kinds

"Payload" is the byte count the kind requires. A frame breaking a rule here is error
`field`. Checked in this order: ext (only data may carry one), chan, seq, payload, reason.

| Kind | Code | chan | seq | payload | Sent by |
|---|---:|---|---|---|---|
| data | 1 | any | `>= 1`, per-channel sequence number | 0..n, opaque | sender |
| ack | 2 | any | cumulative: every seq `<= this` is durably committed (0 allowed) | empty | receiver |
| credit | 3 | any | `0` | exactly 8: u64 bytes granted (added to the current credit) | receiver |
| resume | 4 | any | the highest ack this side saw for its sending direction | empty | sender, on each new connection |
| resume_ok | 5 | any | high-water mark: the highest seq the receiver committed | empty | receiver |
| ping | 6 | control | ping id (any) | any (probe size) | either end |
| pong | 7 | control | the ping's seq | the ping's payload | either end |
| close | 8 | control | `0` | 2..125: u16 reason code + UTF-8 reason, at most 123 bytes | either end |

Which direction a frame refers to follows from its kind: `data` and `resume` are about the
sender's direction (handled by the peer's receiver); `ack`, `credit` and `resume_ok` answer
them (handled by the peer's sender). So "chan 1 ack" from the cloud acknowledges the agent's
capture data, and "chan 2 ack" from the agent acknowledges the cloud's commands.

Close reason codes (unknown codes are accepted and reported as they are):

| Code | Name | When |
|---:|---|---|
| 0 | normal | ordinary end |
| 1 | going_away | shutdown or restart |
| 2 | protocol_error | bad frame, gap, ack or commit ahead |
| 3 | too_large | frame over the size limit |
| 4 | credit_exceeded | data beyond the granted credit |
| 5 | resume_conflict | `resume_conflict`, `resume_ahead`, `resume_behind` |
| 6 | internal | the sender failed internally |

The reason text limit is the WebSocket one (RFC 6455 section 5.5: control payload 125 bytes
minus the 2-byte code).

## 4. Decoding

Run the checks in this order and stop at the first failure (the golden vectors expect the
first error):

1. Message longer than `max_frame` (default 1 MiB = 1048576 bytes, configurable): `oversize`.
2. Empty message: `truncated`. Byte 0 is not 1: `version`.
3. Fewer than 24 bytes: `truncated`.
4. Unknown `chan`: `channel`. Unknown `kind`: `kind`. Reserved flag bits: `flags`.
5. If flags bit 0: no byte 24 -> `truncated`; `ext_len` 0 or not a multiple of 9 -> `ext`;
   fewer than `25 + ext_len` bytes -> `truncated`; each entry: tag 0 or a repeated known tag
   -> `ext`.
6. Compare the length with 24 (+ 1 + ext_len) + payload_len: shorter -> `truncated`,
   longer -> `trailing`. Compute in 64 bits (payload_len can be 2^32 - 1).
7. Kind rules of section 3: `field`.

Encoders apply the same kind rules and refuse frames over `max_frame`, so a valid encoder
never produces a frame a valid decoder rejects. A decoder must never crash on any input.

## 5. State machines

### 5.1 Sender (one per channel and direction)

State: `next_seq` (starts at 1), `acked` (starts at 0), the unacknowledged frames
`acked+1 .. next_seq-1` in order, `credit` (bytes), connection state
`disconnected | resuming | open`, and a resend cursor.

- **Send.** Allowed only when `open`, no resend is pending and `payload_len <= credit`.
  Then the frame gets `seq = next_seq++`, credit drops by `payload_len` and the frame is
  kept until acknowledged. Otherwise the send **waits** ("would block": disconnected,
  resuming, resending, credit, closing); data is never dropped. A payload that can never fit
  in `max_frame` is an error at once.
- **Persistence.** The agent stores each frame in its outbox before writing it, deletes rows
  up to `acked` after acks, and after a restart rebuilds the sender from
  `(acked, frames acked+1..)`, which must be data frames numbered without holes.
- **Ack** `a`: `a > last sent` is error `ack_ahead`; `a <= acked` is ignored (stale);
  else frames `<= a` are released and `acked = a`. Acks are valid in any connected state.
- **Credit** `n`: `credit += n` (saturating). Credit belongs to one connection: it is 0
  when a connection starts and void when it ends.
- **Connect.** Credit = 0, state `resuming`, send `resume(seq = acked)`.
- **resume_ok** `h` (only while `resuming`, else `unexpected`): `h > last sent` is
  `resume_ahead`; `h < acked` is `resume_behind` (the peer lost data it had acknowledged);
  else release frames `<= h`, `acked = h`, state `open`, and resend `h+1 .. last sent`
  in order, each one as credit allows and charged like a new send, with `sent_us` set to the
  time of the resend. New data waits until the resend is done, so each channel stays in order.
  An ack that covers frames still waiting to be resent skips them.
- **Disconnect.** State `disconnected`, credit 0, resend cursor cleared; unacknowledged
  frames stay.

### 5.2 Receiver (one per channel and direction)

State: `received` (highest seq accepted in order), `committed` (the high-water mark, hwm;
`committed <= received`), `credit` (bytes granted and not used on this connection).

- **Data** `s` with `payload_len` bytes: more than `credit` is `credit_exceeded`; else
  credit drops by `payload_len` (for **every** data frame, duplicates too, exactly as the
  sender counted it). Then:
  - `s <= received`: **duplicate**, reported, not applied, not an error;
  - `s == received + 1`: **fresh**, `received = s`, the application applies it;
  - `s > received + 1`: **gap**, not accepted; close with `protocol_error` and resume.
- **Commit** `s` (called by the application once frames `<= s` are durable): `s > received`
  is `commit_ahead`; `s <= committed` does nothing; else `committed = s` and the receiver
  sends `ack(seq = s)`. Acks are never sent before the commit.
- **Grant** `n`: `credit += n`, send `credit(n)`. Grant at least one maximum payload, or a
  large frame can never be sent. The default session grants `max_frame - 24` bytes per channel
  on each resume; implementations grant more as they commit.
- **resume** with `last_acked = a`: `a > committed` is `resume_conflict` (this side lost
  committed data); else answer `resume_ok(seq = committed)`, then the initial credit.
- **Rewind.** If frames received but not committed are lost (the store failed, or the
  process restarted), set `received = committed`; their resends are then fresh again.
  A cloud restart rebuilds the receiver with `received = committed = stored hwm`.
- **Disconnect.** Credit = 0.

### 5.3 Session

- Every new connection: each end sends `resume` for all five channels (control first);
  each `resume` is answered with `resume_ok` and the initial credit. Data flows on a channel
  once its `resume_ok` arrived. A fresh agent sends `resume(0)`.
- On disconnect, frames queued and not written are dropped; unacknowledged data is resent
  after the next resume. Applying is idempotent by `(agent, chan, seq)`, so a duplicate the
  receiver failed to recognise (after a rewind) is still harmless.
- **Writer priority:** frames are written control first (every non-data frame, and data on
  the control channel), then data on capture, commands and results (first in, first out
  across the three), then bulk. Within one channel order is always preserved. Bulk has its
  own credit, so it never takes control or capture credit.
- **Ping/pong:** the answer echoes seq, sent_us and payload, so the pinging side measures the
  round trip as `now - sent_us` with its own clock.
- **Close:** after sending `close` no new data is sent; the socket is closed once the queue
  is written. On receiving `close` the end stops and disconnects; outboxes stay for the next
  connection.
- **Errors** in section 5 are protocol violations by the peer: close with the matching code
  and reconnect (with jittered backoff, slice 5).

## 6. Limits

| Limit | Value |
|---|---|
| `max_frame` | 1 MiB (1048576 bytes) default, configurable per end; both ends must agree |
| fixed header | 24 bytes |
| extension | at most 255 bytes of entries (28 entries) |
| close reason | 123 bytes of UTF-8 |
| seq | u64 per channel and direction; exhaustion is an error (`seq_exhausted`) |
| credit | u64 bytes, saturating |

## 7. Error names

Stable names used in logs, golden vectors and the .NET port: `truncated`, `version`,
`oversize`, `channel`, `kind`, `flags`, `ext`, `trailing`, `field` (decoding);
`ack_ahead`, `resume_ahead`, `resume_behind`, `resume_conflict`, `commit_ahead`,
`credit_exceeded`, `wrong_channel`, `unexpected`, `restore`, `seq_exhausted`,
`not_connected` (state machines).

## 8. Golden vectors

`frames.txt` holds blocks separated by blank lines:

```text
name: data_capture_basic
hex: 01010100000000000000000100000000000003e800000003616263
fields: version=1 chan=capture kind=data seq=1 sent_us=1000 payload=616263
```

- `fields`: decoded values; `payload` and `close_reason` in hex; `t_detected_us`,
  `t_read_us`, `credit`, `close_code` only when present.
- `error`: the decode error name of section 7 for a malformed frame.
- `max_frame`: the limit for this vector when it is not the default.
- `mode: decode`: check decoding only (the vector has an unknown extension tag).

A conforming implementation decodes every `hex` to its `fields` (or fails with `error`)
and encodes every `fields` without `mode: decode` to exactly `hex`.
